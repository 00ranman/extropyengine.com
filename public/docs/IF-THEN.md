# If this, then that

People roll their eyes at “smart contract.” Fine. The useful object is older than Ethereum: a named case that runs when both edges already signed.

If the cooler is empty and Tuesday is a standing order, reorder.  
If both edges accepted the claim, the mint gates may fire.  
If the four-week cash ratio is thin, H_cap steps down.  
If the CAT on-duty bit is live, β is on for this ticket.  
If the bit is dark, β drops.

Nobody in a conference room has to pretend that was a decision. A person is for the case the contract does not name yet. Then you write the new if-then. You do not mint a manager caste to babysit the named cases.

## Why the Web3 version stays dumb

On a liquid chain the “then” is usually: move a bag. So every contract inherits the pool. Verification becomes a mint for that sale. People stop asking whether the loop closed and start asking whether the bag printed. That is the handicap. Not the if-then. The bag.

## What is different here

The “then” is not a transfer.

- mint or refuse XP  
- move or refuse CT_W  
- set H_cap from published cash  
- turn β on or off  
- print cash collected and overlay touch  
- park the overlay at 0  

Standing does not list. EP dies on the ticket. So the contract can actually be about the dock, the till, the on-duty bit — not about exit liquidity.

Two computers: classical logic runs the named case. A model at the edge may package the claim. It does not become the ledger. Looking at a graph to hunt WHO still writes a vertex.
